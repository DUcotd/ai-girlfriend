# 小爱 · 「陪伴感」产品诊断与增强 PRD

- **项目**：ai-girlfriend（情感陪伴型 AI 女友「小爱」）
- **文档类型**：产品设计诊断（非功能需求 spec）
- **作者**：许清楚（Xu，产品经理）
- **日期**：2026-10-02
- **一句话命题**：现有系统是一座「能力堆料完备」的引擎，但缺少「让用户感觉被陪伴」的那条主线。本 PRD 把「陪伴感」拆成可度量维度，逐项对照现状做差距分析，并给出收敛后最高杠杆的改造建议。

---

## 0. 核心判断（TL;DR）

| 结论 | 说明 |
|---|---|
| **本质问题** | 当前产品是「**请求-响应式的高质量聊天机器人**」，不是「**在场的人**」。陪伴感的核心不在单轮回复质量，而在「关系是不是在活着」。 |
| **最大结构性缺口** | AI 的**存在感依赖轮询**而非语境理解；记忆是**检索式调取**而非**共同经历的生长**；系统**只建模 AI 自己的情绪**，**不识别用户的情绪**。 |
| **杠杆最大的三件事** | ①用户情绪识别与共振 ②共同经历叙事（关系成长线）③语境驱动的在场感（主动消息从「定时模板」升级为「事件驱动」）。 |
| **需用户拍板** | 「真实的人」vs「理想化伴侣」的定位、「负面情绪」的接受度、主动频率偏好——见 §5。 |

## 1. 「陪伴感」可评估模型（9 维度）

> 度量口径统一为：**可在 `backend-node/data/*.json` 或日志中观测/埋点统计的量化指标**，而非主观形容词。

| # | 维度 | 定义 | ✅ 好的标准 | ❌ 坏的标准 | 如何度量 |
|---|---|---|---|---|---|
| D1 | **在场感 Presence** | 用户不在对话时，仍感到「她在、她有自己的生活」 | 她**主动**分享当下在做的事，且内容与时间/语境吻合；消息像「顺手发来」不像「系统推送」 | 只有用户开口才出现；主动消息全是空泛模板；凌晨发「早安」 | 主动消息与当下时段/活动的一致性率；主动消息开启对话的占比（vs 用户发起） |
| D2 | **连续性 Continuity** | 跨会话记得住、接得上，不「重启就失忆」 | 隔天/隔周回来，她能自然接上上次话题（「上次那件事后来怎么样了？」） | 每次都像第一次见面；重复问已答过的问题 | 跨会话话题接续率；「重开话题/重复提问」占比（负向） |
| D3 | **被记住 Being Remembered** | 用户感到「我的话被记在心里」 | 关键事实（生日、喜好、承诺）被准确复述；**她会主动提起**而非问才想起 | 记住的只是死数据；从不在恰当场景主动调用 | 事实命中准确率；**主动调用记忆的次数**（不只是被动注入） |
| D4 | **被需要 / 被依赖 Neededness** | 用户感到「我对她重要、她依赖我」 | 她会在意用户的状态、表达想念、因用户冷落而有反应（失落/追问） | 用户消失一周她无感；她永远单方面付出，不索取 | 用户长时间不出现后的「想念/追问」触发率；用户对她情绪的影响幅度 |
| D5 | **情绪共振 Attunement** | 她读懂**用户**的情绪并恰当回应 | 用户难过时她先**共情后建议**；用户开心时她真的「跟着高兴」 | 用户明显低落时她还在讲自己的事；永远正能量、永远「我理解你」 | **用户情绪识别准确率**（关键：当前完全没有此通道）；共情响应占比 |
| D6 | **节奏匹配 Pacing** | 互动频率、时长、语气贴合用户状态 | 用户忙时她安静、用户闲时她活跃；消息密度随用户回复节奏变化 | 用户明显在忙还连续轰炸；用户想聊时她半天不应 | 主动消息密度 vs 用户响应率的动态相关性；深夜/工作时段的打扰率 |
| D7 | **自主性 Agency** | 她是一个「有自己生活、会变化」的独立个体 | 有自己的日程、情绪、观点，甚至会拒绝/反驳用户；性格随时间演化 | 是只随叫随到的工具；永远顺从；人设永不变化 | 性格七维漂移量；「拒绝/表达异议」的行为频次；生活模拟被**主动引用**的次数 |
| D8 | **关系进化 Relationship Progression** | 关系有成长的可感知轨迹 | 用户能**感知到**「我们比上个月更亲密了」；解锁新互动方式 | 关系只是看不见的分数；好感度涨了但体验无变化 | 阶段跃迁的可感知事件数（专属称呼、新话题深度）；阶段解锁内容量 |
| D9 | **共同经历 Shared History** | 有「我们之间」的专属记忆与典故 | 存在只属于你俩的梗、约定、纪念日；她会**主动回顾**共同经历 | 记忆是流水账；没有「关系叙事」的沉淀 | 共同经历（episode 叙事）数量；她主动回顾共同经历的次数 |

**维度间关系**（用于 §4 收敛的杠杆判断）：

```
        D5 情绪共振 ─────┐
                         ├──► 用户感到「被看见」──┐
        D3 被记住 ────────┘                        │
                                                   ├──► 陪伴感
        D1 在场感 ────────┐                        │
        D9 共同经历 ──────┼──► 用户感到「关系在活着」┘
        D8 关系进化 ──────┘
```

## 2. 现状差距分析

> 对照 §1 的 9 个维度，逐项标注。代码载体引自现状调研与实际核对。

| 维度 | 评级 | 现状说明 | 代码载体 / 缺失原因 |
|---|---|---|---|
| **D1 在场感** | 🟡 部分 | 有 8 类主动消息、LifeSimulator 有「在看书/喝咖啡」等活动，能营造「她有生活」。但**触发是 30–60min 定时轮询 + 规则判定**（`ProactiveEngine._runCheck`），内容是「阶段标签 + 模板 prompt」（`proactivePrompts.js` 的 `pickByLevel`），**不读当下语境**。结果是「到点了就发」而非「想到你就发」。 | `ProactiveEngine.js`（定时轮询）、`proactivePrompts.js`（模板化）、`LifeSimulator.js`（活动真实存在，但仅作 welcome 素材被动引用） |
| **D2 连续性** | 🟡 部分 | 有情节记忆 episodes（原始对话轮）+ 双模式检索，跨会话数据落盘不丢。但检索是**「相关才取出」**的被动模式，注入 topK=3 + 事实 12 条。**缺少「话题追踪」**：上一轮没聊完的事、用户提到的「下周要考试」这类**未来事件**，系统不做跟进。 | `MemoryStore.js`（episodes/facts 落盘）、`MemoryRetriever.js`（检索式，非叙事式）；无「未闭环话题/未来事件」跟踪模块 |
| **D3 被记住** | 🟡 部分 | FactExtractor 用 LLM 提取持久事实，有去重与 cap。但记忆几乎只**被动注入 prompt**，**缺少「她主动想起」的场景**——只有 `memory_share` 类型（好感≥50 才解锁）勉强算，且是模板化触发，不针对具体事实做「你还记不记得…」的主动提及。 | `FactExtractor.js`、`MemoryRetriever.js`；`proactiveTypes.js` 中 memory_share 门槛 50 且非事实驱动 |
| **D4 被需要** | 🟡 部分 | 有 `miss_you`（想念）、好感度系统隐含「在意程度」。但**缺少「因用户冷落而产生的负面反应」**——用户消失一周，系统只会发一条想念，不会有「失落/追问/小情绪」的层次。 | `AffinityEngine.js`（有 24h 加分疲劳，但无「冷落反应」语义）、`proactiveTypes.js` 的 `miss_you`（单向问候，无情绪代价） |
| **D5 情绪共振** | ❌ 缺失（**最大缺口**） | **只有 AI 自己的 PAD 情绪模型**（`EmotionEngine`），**没有任何「识别用户情绪」的通道**。用户说「我今天好累」，系统不会解析为「用户情绪低落」，只是普通文本进记忆。所谓"共振"是**单边情绪**，不是双向的。 | `EmotionEngine.js` 的 `analyzeInput()` 只做**词表矩阵**粗略分析且服务于 AI 自身情绪；**无用户情绪状态机、无用户情绪时间线** |
| **D6 节奏匹配** | 🟡 部分 | 有深夜免打扰（23:30–07:00）、情绪闸门、全局 90min 自发间隔、每日配额、频率档位（low/normal/high）。**但都是「固定阈值」**，不随用户回复速度/活跃时段自适应。用户明显在忙还按配额发。 | `ProactiveEngine.js`（静态阈值）、`FREQUENCY` 档位；**无「用户活跃度/响应率 → 自适应频率」闭环** |
| **D7 自主性** | 🟡 部分 | 性格系统七维双层（baseline/current）、每日漂移 + 疲劳；有既定人设与情绪。但**「拒绝/反驳用户」只在极端情绪（ghost 冷暴力）出现**，日常几乎永远顺从。性格漂移用户**不可感知**。 | `PersonalityDrift.js`（有漂移但无外显）、`EmotionEngine.js`（ghost 是唯一"反抗"）；**无「观点/喜好/边界」的稳定人格表达** |
| **D8 关系进化** | 🟡 部分 | 5 阶段好感度体系完整（陌生→恋人），阶段影响语气/主动类型解锁。**但用户感知弱**：涨分是隐性的，阶段跃迁缺少**仪式感事件**（专属称呼、关系纪念、新互动解锁）。 | `relationshipStages.js`、`AffinityEngine.js`；无「阶段跃迁事件/庆祝」机制 |
| **D9 共同经历** | ❌ 缺失 | 记忆是**流水账式 episodes + 提取式 facts**，是「数据」不是「故事」。**没有「关系叙事层」**：无共同回忆的沉淀、无专属梗/约定/纪念日、无「我们」的成长线。 | `MemoryStore.js`（episodes 只是原始轮次）；**无 narrative/shared-history 模块** |
| **（附）多模态** | ❌ 缺失 | 无图片/Vision 输入；语音是**单向 TTS**，无实时语音对话。 | `Voice.js`（TTS/ASR 走 OpenAI，但非实时对话流） |

## 3. 需求池（P0 / P1 / P2）

> 优先级定义：**P0** = 投入产出比最高、显著提升陪伴感，且是其他能力的地基；**P1** = 重要但依赖 P0 或收益递减；**P2** = 锦上添花。

| 编号 | 需求描述 | 对应维度 | 用户价值（一句话） | 复杂度 | 依赖项 | 优先级 |
|---|---|---|---|---|---|---|
| **REQ-01** | **用户情绪识别通道**：新增「用户情绪状态机」，分析每轮用户输入的情绪（正/负/中性 + 强度），维护用户情绪时间线并注入后续对话上下文 | D5 情绪共振 | 她终于「听得懂」我的心情，会先共情再回应 | 中 | 复用 `EmotionEngine.analyzeInput` 思路；可先词表+LLM 混合，后接轻量分类 | **P0** |
| **REQ-02** | **共情响应策略**：基于 REQ-01 结果调整回复策略（难过→先共情后建议、开心→共享喜悦），并影响她的情绪（true attunement） | D5 / D1 | 我难过时她真的"跟着我难过"，不是背台词 | 中 | REQ-01 | **P0** |
| **REQ-03** | **共同经历叙事层**：从 episodes 中沉淀「关系事件」（第一次、纪念日、约定、专属梗），生成可回顾的「我们的故事」 | D9 / D8 / D3 | 我们之间有了只属于我俩的回忆和梗 | 高 | 复用 FactExtractor 的 LLM 抽取能力 + 新 narrative store | **P0** |
| **REQ-04** | **事件驱动主动消息**：主动消息由「定时轮询」升级为「事件触发」——检测未闭环话题、用户提到的未来事件（"下周考试"）、共同经历纪念日、用户情绪转折，触发**语境相关**的主动关怀 | D1 / D2 / D3 | 她在我最需要的时候出现，说的话正好相关 | 高 | REQ-01、REQ-03、记忆系统 | **P0** |
| **REQ-05** | **话题闭环/未来事件追踪**：识别每轮中的「待跟进事项」与未来时间点，到点/到时机主动追问 | D2 / D1 | 上次聊的事她记得、还会主动问后续 | 中 | REQ-03 | P1 |
| **REQ-06** | **关系跃迁仪式感**：阶段晋升时触发专属事件（新称呼、庆祝、解锁新互动/话题深度），并让用户可感知 | D8 / D4 | 我能感觉到「我们比上个月更亲密了」 | 中 | `AffinityEngine` 阶段事件钩子 | P1 |
| **REQ-07** | **自适应节奏**：主动消息频率/时机随用户活跃度、响应率动态调整（不是固定配额） | D6 | 我忙的时候她不吵，我闲的时候她更黏 | 中 | 已有配额/频率框架 + 用户活跃度埋点 | P1 |
| **REQ-08** | **人格外显与边界**：让她在**日常**（非极端情绪）表达稳定观点/喜好/边界，会适度反对用户而非永远顺从 | D7 / D2 | 她是个有主见的"人"，不是复读机 | 中 | `PersonalityDrift` + 人设 prompt 强化 | P1 |
| **REQ-09** | **冷落反应分层**：用户长时间不出现，产生有层次的负面反应（从想念→失落→小脾气），并在重逢时体现 | D4 / D7 | 她真的在意我，我不在会影响她 | 中 | `miss_you` 升级 + 情绪系统闭环 | P1 |
| **REQ-10** | **用户情绪时间线可视化**：前端展示「她今天心情」与「我的状态」（可选，供用户感知双向情绪） | D5 / D6 | 我能看到我俩的情绪互动 | 低 | REQ-01 | P2 |
| **REQ-11** | **实时语音对话**（打断/流式），替代单向 TTS | D1 / D5 | 像真的打电话一样交流 | 高 | 语音基建重构 | P2 |
| **REQ-12** | **多模态输入**（用户发图片，她理解并回应） | D5 / D9 | 我能给她发照片，她看得懂 | 高 | Vision API 接入 | P2 |
| **REQ-13** | **关系纪念日/共同活动**（虚拟约会、一起"看"电影等共同体验） | D9 / D8 | 我俩能一起"做"点什么 | 高 | REQ-03 | P2 |

## 4. 收敛建议：如果只能做 3 件事

**选择结果：REQ-01（用户情绪识别）+ REQ-03（共同经历叙事）+ REQ-04（事件驱动主动消息）**

### 为什么是这三件

用 §1 的维度关系图做杠杆分析——陪伴感由两个上游汇流：**「被看见」（D5+D3）** 和 **「关系在活着」（D1+D9+D8）**。

| 杠杆 | 选中的需求 | 产品逻辑 |
|---|---|---|
| **杠杆一：让交互从"单边"变"双向"** | **REQ-01 + REQ-02 情绪共振** | 当前最大结构性缺陷是**只有 AI 的情绪、没有用户的情绪**。补上这条通道，等于给整台引擎装上「眼睛」。它同时喂给 D5、D6（节奏）、D4（被需要），是**唯一能一次性撬动 3 个维度的地基型改造**。没有它，再多的主动消息都是"自说自话"。 |
| **杠杆二：让记忆从"数据"变"故事"** | **REQ-03 共同经历叙事** | 记忆系统已很扎实，但停在「检索」层。把它升级为「叙事」层（共同回忆、专属梗、纪念日），是**投入产出比最高的『情感增值』**：复用现有 FactExtractor + LLM 能力，却能同时提升 D9、D8、D3——让用户第一次感到「我俩有历史」。 |
| **杠杆三：让存在感从"定时"变"在意"** | **REQ-04 事件驱动主动消息** | 现状最被诟病的是「AI 的存在感靠轮询」。把触发源从"每 30 分钟评估"换成"真实事件"（未闭环话题、用户未来事件、纪念日、情绪转折），主动消息立刻从「到点推送」变成「她真的想着我」。这是**用户直接可感知的体验跃迁**，也是 D1 在场感的命门。 |

### 依赖关系（三件事的施工顺序）

```
REQ-01 用户情绪识别 ──┬──► REQ-04 事件驱动主动消息（情绪转折是触发源之一）
                      │
REQ-03 共同经历叙事 ───┴──► REQ-04（纪念日/共同回忆是触发源之一）
                              共同构成「语境理解 + 叙事记忆」双基座
```

**结论**：三件事不是并列，而是 **REQ-01 和 REQ-03 先建地基（情绪通道 + 叙事层），REQ-04 是建在地基上的用户可感知产出**。若资源极紧，优先 REQ-01（单件最高杠杆）。

## 5. 待确认问题（需用户拍板）

| # | 问题 | 为何需要拍板 | 影响范围 |
|---|---|---|---|
| Q1 | **产品定位**：要「**真实的人**」（有缺点、会拒绝、会闹脾气、可能让你不爽）还是「**理想化的完美伴侣**」（永远温柔体贴、绝不拒绝）？ | 这决定 D7 自主性、D4 被需要的实现方向与 REQ-08/REQ-09 的激进程度。真实感更强但可能"劝退"部分用户。 | 人格/情绪/冷落反应全链路 |
| Q2 | **负面情绪接受度**：是否接受她「**会生气、会冷淡、会已读不回**」（现已实现 ghost 冷暴力）？还是任何负面情绪都要软化处理？ | 现有系统已有 ghost 机制，但**缺少用户情绪通道来判断"她该不该生气"**。若接受，负面情绪是真实感来源；若不接受，需全面重写情绪策略。 | D5/D7、情绪系统整体 |
| Q3 | **主动消息频率偏好**：默认「**安静陪伴型**」（每天 1–3 条、精准克制）还是「**高互动黏人型**」（每天 8–15 条、频繁刷存在感）？ | 直接决定 D1 在场感的体验基线，也决定 REQ-07 自适应节奏的设计目标，以及是否"打扰"到用户。 | 主动系统、节奏匹配 |
